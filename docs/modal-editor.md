# 手动编辑弹框与按钮图标修正

状态：开发中。只使用正式插件 API 1.4，可安装到正式 OpenIDEA 0.1.40，不需要宿主补丁。

## 交互

- 点击 Edit Commit Message Fields，打开一个居中的字段列表弹框，不增加右侧工具窗口入口。
- 列表每行是一个字段及其当前值：类型、scope、subject、正文、破坏性变更、issue、Skip CI。字段显隐、类型排序和默认值继续由设置决定。末尾是 Write to commit message 和 Clear all fields。
- 选中字段后在各自的弹框中编辑，确认后回到列表。类型和 Skip CI 从列表中选择（Skip CI 含“不写入标记”），scope、subject、issue 用单行输入，正文和破坏性变更用多行输入。
- Write 先校验再替换提交草稿，成功即关闭。标题非法、无仓库或草稿已变化时不写入，列表重新出现并以原因作为标题，字段保持不变。
- 关闭列表（取消或 Esc）保留草稿，下次打开恢复。单个字段弹框取消时该字段保持原值。
- 草稿按当前 Git 仓库隔离。标识来自已授权的 `vcs.read`，不增加 `project.read`。读取草稿后的修改仍由 revision 保护。

## 为什么不是单个表单

正式 API 1.4 没有多字段弹框：`pick`、`input`、`input-multiline`、`confirm` 都是居中的单值对话框；视图只能停靠在 left、right、bottom、services，custom editor 和 content tab 位于编辑器标签页。

曾在本地宿主上实现过可选的 `form-dialog@1.5.0` 接口，并在隔离开发版中验收通过。但正式 0.1.40 无法加载这样的组件：安装时 engines 检查拒绝 `^1.5`，运行时版本检查也会拒绝导入 1.5 接口的组件。插件必须能装在正式版上，因此改用字段列表，放弃“七个字段在同一弹框同时编辑”。这项要求主要影响从零填写多个字段时的效率；日常的类型加标题场景只多几次点击。

与单个表单相比有两处差异：字段要逐个编辑；单个字段弹框取消时宿主只返回空值，弹框里尚未确认的输入不会保留。

## 图标问题

正式宿主对包内命令 SVG 异步加载，但提交工具栏只在注册时读取一次动作图标，因此四个按钮缓存了同一个插件默认图标。本插件改用宿主已有的 `diff-magic`、`review-comment`、`list`、`edit`，四个动作同步得到不同图标，不依赖宿主修复。

## 验证记录

- 命令级测试按 `pick` / `input` 应答序列驱动 `manual`，覆盖逐项编辑并写入、关闭列表后恢复草稿、单个字段取消保持原值、非法标题回到列表并保留字段。这些测试在旧的表单实现上先失败，然后通过。
- 编辑器测试覆盖列表内容与显隐、多行值预览、类型排序、Skip CI 默认值与“不写入标记”、清空、按仓库隔离草稿、空标题、无仓库和非法标题时列表标题显示原因。
- 组件只引用 `openidea:plugin/*@1.4.0` 接口。
- 图标在隔离开发版中确认四个按钮各自显示不同的 SVG。该开发版带有表单补丁，但图标修复只用到 1.4 已有能力。
